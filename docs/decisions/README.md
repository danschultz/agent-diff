# Decisions

Each file records one design decision: the problem, the solution, its tradeoffs,
and the follow-up design choices it leaves open. See
[`.rules/decisions.md`](../../.rules/decisions.md) for how to add one. Terms are
defined in the [glossary](../glossary.md).

| Decision                                                                                                                                                               | Status                                                                                                                                                                                                                                                                                                        | Summary                                                                                                                                                                                                                                                                             |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [0001: The UI is a local web app](0001-local-web-app.md)                                                                                                               | Accepted                                                                                                                                                                                                                                                                                                      | A local server reads the repos and serves the review UI to a browser or cmux browser surface.                                                                                                                                                                                       |
| [0002: The file view can show unchanged files](0002-show-unchanged-files.md)                                                                                           | Accepted                                                                                                                                                                                                                                                                                                      | Only changed files are listed by default, and a toggle lists unchanged files so the reviewer can read the code around a change.                                                                                                                                                     |
| [0003: The reviewer can open the code in an IDE](0003-open-in-ide.md)                                                                                                  | Accepted, amended by [0013](0013-working-directories.md)                                                                                                                                                                                                                                                      | The reviewer can open the working directory, the branch, or a file at a line in an editor such as VS Code or IntelliJ.                                                                                                                                                              |
| [0004: The agent tree is an input, not inferred](0004-agent-tree-is-an-input.md)                                                                                       | Accepted, amended by [0009](0009-review-sessions-and-claims.md)                                                                                                                                                                                                                                               | Agents and harnesses report the agent tree when agents are spawned. The app doesn't infer agents from git.                                                                                                                                                                          |
| [0005: Agents are notified of feedback, then pull it from the server](0005-notify-then-pull-feedback.md)                                                               | Accepted, amended by [0009](0009-review-sessions-and-claims.md), [0010](0010-user-prompts-agent-to-fetch-review.md), [0011](0011-api-core-with-cli-client.md), [0018](0018-agents-list-open-comments.md), and [0036](0036-the-reviewer-submits-reviews-and-the-agent-gets-a-review-message.md)                | Submitted feedback triggers a short notification that wakes an idle agent, which then fetches the comments from the server. Agents never block waiting for review.                                                                                                                  |
| [0006: Review state is stored in SQLite](0006-sqlite-review-state.md)                                                                                                  | Accepted, amended by [0010](0010-user-prompts-agent-to-fetch-review.md), [0018](0018-agents-list-open-comments.md), and [0036](0036-the-reviewer-submits-reviews-and-the-agent-gets-a-review-message.md)                                                                                                      | Review sessions, reviews, comments, claims, and delivery status are stored in a SQLite database, so they can be restored after a crash or restart.                                                                                                                                  |
| [0007: The UI live-reloads by watching the file system](0007-live-reload-from-file-watching.md)                                                                        | Accepted                                                                                                                                                                                                                                                                                                      | The server watches each working directory's files and git state, so changes from any agent or human update the UI.                                                                                                                                                                  |
| [0008: Comments are re-anchored in layers and marked outdated rather than guessed](0008-comment-reanchoring.md)                                                        | Accepted, amended by [0018](0018-agents-list-open-comments.md) and [0036](0036-the-reviewer-submits-reviews-and-the-agent-gets-a-review-message.md)                                                                                                                                                           | Comments follow code by diff mapping, then strict content matching, and are otherwise marked outdated. The file contents each comment was written on are saved and shared.                                                                                                          |
| [0009: Reviews are submitted to review sessions, and agents claim feedback per working directory](0009-review-sessions-and-claims.md)                                  | Accepted, amended by [0010](0010-user-prompts-agent-to-fetch-review.md), [0013](0013-working-directories.md), and [0018](0018-agents-list-open-comments.md)                                                                                                                                                   | An actor starts a review session over a list of working directories, reviews are submitted to it, and agents take an expiring claim on a working directory to address its feedback.                                                                                                 |
| [0010: The user prompts the agent to fetch the latest review](0010-user-prompts-agent-to-fetch-review.md)                                                              | Superseded by [0036](0036-the-reviewer-submits-reviews-and-the-agent-gets-a-review-message.md)                                                                                                                                                                                                                | After submitting a review, the reviewer tells the agent to apply it, and the agent fetches the most recent review with `agent-diff review`. The review server never contacts agents.                                                                                                |
| [0011: The review server has an API, and agents use a CLI that calls it](0011-api-core-with-cli-client.md)                                                             | Accepted, amended by [0018](0018-agents-list-open-comments.md) and [0019](0019-cli-does-not-start-the-server.md)                                                                                                                                                                                              | The review server's HTTP API is the core, used by the review UI and by the `agent-diff` CLI, which agents and harnesses use. There's no MCP server.                                                                                                                                 |
| [0012: The review UI renders diffs with CodeMirror](0012-codemirror-renders-diffs.md)                                                                                  | Accepted                                                                                                                                                                                                                                                                                                      | CodeMirror 6 with `@codemirror/merge` renders diffs, chosen over Monaco, git-diff-view, and a custom table after measuring load time, memory, live reload, and scrolling.                                                                                                           |
| [0013: Review sessions cover working directories, which don't have to use git](0013-working-directories.md)                                                            | Accepted, amended by [0018](0018-agents-list-open-comments.md)                                                                                                                                                                                                                                                | A working directory is any directory, git or not. Only files under it are shown, the branch is whatever `HEAD` points to, and directories that don't use git show all files with no diffs.                                                                                          |
| [0014: Briefs on GitHub are implemented by headless agent sessions](0014-implement-briefs-headlessly.md)                                                               | Accepted, amended by [0015](0015-closing-a-brief-clears-its-labels.md), [0030](0030-self-review-before-the-pull-request-opens.md), [0034](0034-briefs-are-aven-tasks.md), [0035](0035-queued-briefs-wait-for-their-blockers.md), and [0039](0039-dan-retries-a-failed-brief-by-resuming-its-agent-session.md) | `implement` starts a headless agent session in its own worktree for each brief written as a GitHub issue, opens a pull request, and alerts Dan through GitHub and the Claude app when the agent session needs Dan.                                                                  |
| [0015: Closing a brief's issue clears its agent labels, in a GitHub Actions workflow](0015-closing-a-brief-clears-its-labels.md)                                       | Superseded by [0034](0034-briefs-are-aven-tasks.md)                                                                                                                                                                                                                                                           | A workflow removes every `agent:*` label from an issue when it's closed. `implement` doesn't touch labels when it finishes with a brief, and closing a pull request without merging leaves its issue open.                                                                          |
| [0016: The review UI's state is held in TanStack Store, updated through Immer](0016-tanstack-store-with-immer.md)                                                      | Accepted                                                                                                                                                                                                                                                                                                      | Stores are created with a `createImmerStore` helper over TanStack Store and Immer, so their types are inferred, updates are plain assignments, and mutating read state is caught by `tsc` and at run time.                                                                          |
| [0017: The `agent-diff` CLI is built with Crust](0017-crust-builds-the-cli.md)                                                                                         | Accepted                                                                                                                                                                                                                                                                                                      | The CLI uses `@crustjs/core` and `@crustjs/extensions`, chosen for typed arguments, clean errors and piped output, small size, and optional agent-facing packages, accepting that Crust is young, 0.x, and mostly one maintainer's work.                                            |
| [0018: Agents list a review session's open comments and mark each one addressed](0018-agents-list-open-comments.md)                                                    | Accepted, amended by [0036](0036-the-reviewer-submits-reviews-and-the-agent-gets-a-review-message.md) and [0038](0038-agents-reply-in-comment-threads.md)                                                                                                                                                     | The reviewer leaves line and overall comments with no drafts, submit, reviews, or claims, agents list open comments by review session ID and mark each one addressed, and review sessions are archived or deleted.                                                                  |
| [0019: The CLI doesn't start the review server](0019-cli-does-not-start-the-server.md)                                                                                 | Accepted                                                                                                                                                                                                                                                                                                      | `agent-diff server start`, `stop`, and `status` manage the review server, and every other command fails with a clear error when it isn't running.                                                                                                                                   |
| [0020: CLI commands are noun then verb](0020-cli-commands-are-noun-then-verb.md)                                                                                       | Accepted                                                                                                                                                                                                                                                                                                      | Every command is `agent-diff <noun> <verb>`, such as `session new` and `comment list`, so names are predictable and never confused with arguments.                                                                                                                                  |
| [0021: The review server's API is built with oRPC, and validated with Valibot](0021-orpc-and-valibot-build-the-api.md)                                                 | Accepted, amended by [0025](0025-contract-first-orpc-over-rpc.md)                                                                                                                                                                                                                                             | Routes declare Valibot schemas for input, output, and errors, the server implements them with oRPC, and the review UI and CLI call them through oRPC's typed client, with pushed updates as event iterators over SSE.                                                               |
| [0022: Review state is stored with `node:sqlite` and plain SQL, and migrated with dbmate](0022-node-sqlite-plain-sql-and-dbmate.md)                                    | Accepted                                                                                                                                                                                                                                                                                                      | The review server queries SQLite with Node's built-in synchronous driver and hand-written SQL, and runs dbmate's SQL migrations when it starts.                                                                                                                                     |
| [0023: Each user runs one review server for every review session](0023-one-review-server-for-every-review-session.md)                                                  | Accepted                                                                                                                                                                                                                                                                                                      | `agent-diff server start` starts the user's review server, which every review session, CLI command, and the review UI share, and which is the only process that opens the user's database.                                                                                          |
| [0024: A config file in the user's state directory holds their port and token, next to the database](0024-config-file-holds-port-and-token.md)                         | Accepted, amended by [0031](0031-the-review-ui-gets-the-token-in-the-url-fragment.md)                                                                                                                                                                                                                         | The first `server start` creates `$XDG_STATE_HOME/agent-diff` with a config file holding a random port and a stable token that only the user can read, the database sits beside it, and `server start` prints a URL for the review UI that carries the token.                       |
| [0025: The API is declared contract-first, and called over oRPC's RPC protocol](0025-contract-first-orpc-over-rpc.md)                                                  | Accepted                                                                                                                                                                                                                                                                                                      | The contract is declared with `@orpc/contract` in `packages/shared`, the review server implements it and serves it with `RPCHandler`, and the CLI and the review UI call it through `RPCLink`.                                                                                      |
| [0026: The code is split into npm workspaces on TypeScript 7, and only the review UI is built](0026-workspaces-typescript-7-and-test-stack.md)                         | Accepted, amended by [0032](0032-hono-serves-the-api-and-the-review-ui.md)                                                                                                                                                                                                                                    | `shared`, the review server, the CLI, the review UI, and `implement` are npm workspaces on TypeScript 7, only the review UI is built, the review server serves it, SQL is formatted as SQLite, and Playwright tests the whole path.                                                 |
| [0027: The pre-commit hook runs only fast checks, and tests that run git use a hermetic environment](0027-pre-commit-runs-only-fast-checks.md)                         | Accepted                                                                                                                                                                                                                                                                                                      | The hook runs only formatting, the doc lint and the typecheck, `npm run check` and CI run everything, and tests that run git build their environment from an allowlist, so a commit can't change the repo it's made in.                                                             |
| [0028: The project defines how agent sessions work, and `implement` adds only what running unattended needs](0028-the-project-defines-how-agent-sessions-work.md)      | Accepted                                                                                                                                                                                                                                                                                                      | A committed `.claude/settings.json` sets the model and effort for every agent session in the repo, sub-agents live in `.claude/agents/` and rules in `.rules/`, and `implement` passes only what running unattended needs.                                                          |
| [0029: Code is written test-first](0029-code-is-written-test-first.md)                                                                                                 | Accepted                                                                                                                                                                                                                                                                                                      | Every change in every package starts with a test seen to fail for the expected reason, then the least code that passes it, then a refactor, and a bug fix starts with a test that reproduces the bug. Performance fixes are the only exception.                                     |
| [0030: Agent sessions started by `implement` self-review before opening a pull request, and wait for CI](0030-self-review-before-the-pull-request-opens.md)            | Accepted, amended by [0034](0034-briefs-are-aven-tasks.md)                                                                                                                                                                                                                                                    | A `self-review` sub-agent that can't edit files reviews the diff in up to 2 rounds before the pull request opens, judging performance against the sizes in `.rules/performance.md`, its findings are listed in the pull request, and the brief moves to review only once CI passes. |
| [0031: The review UI gets the token in the URL fragment and sends it in a header, with no cookie](0031-the-review-ui-gets-the-token-in-the-url-fragment.md)            | Accepted                                                                                                                                                                                                                                                                                                      | Every API call carries the token as a bearer token and names the review server in its `Host` header, and the review UI saves the token from the printed URL's fragment in `localStorage`, because a cookie would reach other users' review servers on other ports.                  |
| [0032: The review server serves the API and the review UI with Hono](0032-hono-serves-the-api-and-the-review-ui.md)                                                    | Accepted                                                                                                                                                                                                                                                                                                      | Hono, through `@hono/node-server`, passes `/api` to oRPC's fetch `RPCHandler` and serves the built review UI with `serveStatic`, with the API as a sub-app mounted with `.route` whose first middleware checks `Host`.                                                              |
| [0033: Breaking changes are allowed during early development](0033-breaking-changes-are-allowed-during-early-development.md)                                           | Accepted                                                                                                                                                                                                                                                                                                      | Changes don't need to keep working with what earlier versions wrote or accepted, and agent sessions don't write compatibility code unless a brief asks.                                                                                                                             |
| [0034: Briefs are Aven tasks, and only pull requests stay on GitHub](0034-briefs-are-aven-tasks.md)                                                                    | Accepted, amended by [0035](0035-queued-briefs-wait-for-their-blockers.md) and [0039](0039-dan-retries-a-failed-brief-by-resuming-its-agent-session.md)                                                                                                                                                       | `implement` takes briefs from tasks in the Aven project `agent-diff`, holds their state in the `agent` metadata, reports in notes, keeps Aven refs off GitHub, and lets a brief go when its pull request is merged or closed or Dan finishes with the task.                         |
| [0035: A queued brief waits until the tasks it depends on are done](0035-queued-briefs-wait-for-their-blockers.md)                                                     | Accepted                                                                                                                                                                                                                                                                                                      | `implement` starts a queued brief only once every task it depends on in Aven is `done`, leaves one with an open blocker queued without using a slot, and sends back one with a `canceled` or deleted blocker.                                                                       |
| [0036: The reviewer submits reviews, and the review server sends the agent a review message](0036-the-reviewer-submits-reviews-and-the-agent-gets-a-review-message.md) | Accepted                                                                                                                                                                                                                                                                                                      | Comments and replies are drafts until the reviewer submits a review, which sends the listening agent session a short review message naming `agent-diff review show <review-id>`, held until a listener connects and copyable from the review UI.                                    |
| [0037: Agents get review messages through a listener they start on the review session](0037-agents-get-review-messages-through-a-listener-they-start.md)               | Accepted                                                                                                                                                                                                                                                                                                      | The agent runs `agent-diff session listen <session-id>` with the Monitor tool in Claude Code or as a watched background shell in the Cursor CLI, and review messages are addressed by review session ID.                                                                            |
| [0038: Agents reply in comment threads, marking each comment addressed or needs input](0038-agents-reply-in-comment-threads.md)                                        | Accepted                                                                                                                                                                                                                                                                                                      | Every comment is a thread, the agent replies with `agent-diff comment reply` and `--addressed` or `--needs-input`, and the reviewer resolves a comment or reopens it with a reply sent in the next review.                                                                          |
| [0039: Dan retries a failed brief with `agent=retry`, which resumes its agent session](0039-dan-retries-a-failed-brief-by-resuming-its-agent-session.md)               | Accepted                                                                                                                                                                                                                                                                                                      | Dan sets `agent=retry` on a failed brief, and `implement` resumes its agent session in the kept worktree with `claude --bg --resume`, passing on the notes added since it failed, and never retries a brief by itself.                                                              |
